# Структура файлов: `ExportCm.xml` и таблица «расписание по предметам»

Разбор сделан по реальным файлам (школьное расписание, неделя 14.09.2026–20.09.2026):
51 класс, 89 учителей, 34 предмета, 74 кабинета, 755 записей учебного плана, 14 звонков,
1616 ссылок на занятия в расписании.

---

## 1. `ExportCm.xml` — обменный формат расписания (TimeTableExchange)

Технические детали: кодировка **windows-1251** (объявлена в декларации `<?xml ... encoding="windows-1251"?>`),
переводы строк **LF**, отступ — 2 пробела на уровень, пустые элементы закрываются как ` />`,
файл заканчивается тегом `</TimeTableExchange>` без завершающего перевода строки.
Ссылка на схему: атрибут `noNamespaceSchemaLocation="TimeTableWeek.xsd"` (самой xsd в комплекте нет).

Корень `<TimeTableExchange>` содержит 6 секций строго в этом порядке:

```
TimeTableExchange
├── LessonTimes        сетка звонков
├── teachers           справочник учителей
├── subjects           справочник предметов (+ кто может вести)
├── Rooms              справочник кабинетов
├── Plan               учебный план: классы и их «класс-предмет-группы» (csg)
└── TimeTable          само расписание недели — только ссылки на id из Plan/Rooms
```

### 1.1 `LessonTimes` — звонки
```xml
<LessonTime id="2" starttime="08:30" endtime="09:10" sm="1" number="1" />
```
| атрибут | смысл |
|---|---|
| `id` | идентификатор звонка; в файле `id = number + 1` |
| `number` | номер урока, **начиная с 0** (`0` — «нулевой» урок, у школы это «Разговоры о важном») |
| `starttime/endtime` | время начала и конца |
| `sm` | смена (в файле везде `1`) |

В эталоне 14 звонков (`number` 0…13). Расписание ссылается на них через `Lesson/@timeId`.

### 1.2 `teachers` — учителя
```xml
<teacher tid="334473" lastname="Авдеева" firstname="Елена" middlename="Юрьевна" />
```
Только справочник: `tid` + ФИО. В расписании учителя не упоминаются — они «зашиты» в записях плана (см. `csg/@tid`).

### 1.3 `subjects` — предметы
```xml
<subject sid="84412" name="Алгебра и начала математического анализа" abbr="Алгебра и начала мат. анализа">
  <teacher tid="20767" />   <!-- кто может вести предмет -->
</subject>
```
`sid` — идентификатор предмета, `abbr` — короткое имя (именно по нему в таблице встречаются «ДНКР», «ОБЗР»).

### 1.4 `Rooms` — кабинеты
```xml
<room id="25956" name="306" seats="26" floor="3" />
```
`name` — то, что видит человек («306», «Спортивный зал 1»). В расписании используется только `id`.

### 1.5 `Plan` — учебный план (самая важная секция)
```xml
<class id="293196" name="1А" grade="1" studcnt="26" boys="13" girls="13">
  <csg pclassid="293196" id="2460577" tid="1146521" sid="84278" name="Русский язык"
       groupid="" parentsubjectid="" hrsweek="5" studcnt="0" />
</class>
```
* `<class>` — класс школы (`id`, `name`, `grade`, численность).
* Вложенные `<csg>` — строки плана «**c**lass-**s**ubject-**g**roup»: именно их `id` стоят в расписании.
  | атрибут | смысл |
  |---|---|
  | `id` | уникальный id строки плана — ключ расписания |
  | `pclassid` | класс-владелец; **может отсутствовать** (см. ниже) |
  | `tid` | учитель, за которым закреплена строка |
  | `sid` | предмет из `<subjects>` |
  | `name` | «Предмет» или «Предмет/метка группы» |
  | `groupid` | id группы (пусто, если класс не делится) |
  | `hrsweek` | часов в неделю |
  | `studcnt` | учеников в группе (0 — группа без фиксированного состава) |

  Варианты «метки группы» в `name` (после `/`):
  * пусто — урок всего класса;
  * `(п.1)`, `(п.2)`, `подгруппа 1` — деление класса на группы (англ. язык, информатика, технология…);
  * `Труд (техн. м.)` — деление по полу;
  * `4б` — весь класс оформлен как группа;
  * фамилия (`Русский язык/Галкин`) — индивидуальные занятия одного ученика.

  **Особенность:** у класса `4б` все 21 строка плана записаны **без атрибута `pclassid`**
  (индивидуальное обучение), но физически вложены внутрь `<class id="...4б">`.
  Такие строки тоже используются в расписании, поэтому принадлежность классу определяется
  и по вложенности, а не только по атрибуту.

### 1.6 `TimeTable` — расписание недели
```xml
<TimeTable>
  <Week id="1" name="Неделя 14.09.2026 - 20.09.2026">
    <Day id="1" name="понедельник" wd="2">
      <Lesson timeId="2">
        <csg id="2460075" roomid="25956" />
        <csg id="2546581" />                      <!-- без кабинета -->
      </Lesson>
    </Day>
  </Week>
</TimeTable>
```
* `Day/@wd`: 2 = понедельник … 7 = воскресенье (как в `Date.getDay()` + 1).
* `Lesson/@timeId` — id звонка из `LessonTimes` (т.е. номер урока + 1).
* Внутри `<Lesson>` — **только ссылки**: `csg/@id` (строка плана → класс, предмет, учитель, группа)
  и необязательный `roomid`. Никаких названий в расписании нет.
* Одна и та же строка плана (`csg id`) встречается в неделе столько раз, сколько уроков
  (в идеале = `hrsweek`, на практике бывают расхождения).
* `csg` без `pclassid` тоже встречаются в расписании (31 ссылка в эталоне).
* Порядок `<csg>` внутри `<Lesson>` произвольный; часть строк плана в расписании не используется;
  часть уроков стоит без кабинета (`roomid` отсутствует).

**Вывод:** чтобы построить такой XML из таблицы, нужны не названия, а именно id из секций
`Plan`/`Rooms`/`LessonTimes`/`Day` — поэтому конвертер обязательно требует эталонную выгрузку.

## 2. Таблица Excel «расписание по предметам»

Один лист (`Лист1`), сетка «день × номер урока × класс»:

| A «Дни» | B «Уроки» | C… «1а», «1б», … «11и» |
|---|---|---|
| Пн | 0 | Разговоры о важном (105) |
|    | 1 | Русский язык (105) |

* Шапка в строке 1: `A1 = «Дни»`, `B1 = «Уроки»`, далее названия классов (50 колонок).
* Колонка A: сокращённое название дня; значение стоит только в первой строке блока дня
  (или в объединённой ячейке) — дальше идёт «продолжение».
* Колонка B: номер урока **0…9** (0 — нулевой урок).
* Ячейка занятия: `Предмет (кабинет)`. Варианты:
  * `Математика (311)` — обычный урок;
  * `Иностранный язык (английский) (305,307)` — **один предмет, два кабинета** = две группы класса;
  * `Информатика, Труд (технология) (320,110)` — **два предмета, два кабинета** = деление класса пополам;
  * запятые внутри скобок (`Иностранный язык (английский)`) разделителями не считаются.
* Колонка `11и` соответствует **двум** классам системы: `11и (ест.-научн.)` и `11и (техн.)`.
* Названия в таблице «человеческие» и не совпадают с системными: регистр (`1а`/`1А`),
  порядок слов (`Иностранный язык (английский)`/`Иностранный (английский) язык`),
  аббревиатуры (`ДНКР`, `ОБЗР`), «хвосты» (`Химия_`), свои имена кабинетов
  (`спорт.зал`, `спорт.зал2`, `акт.зал`, `БАС`, `IT куб 1`, `каб.пр.дея`, `112`).
* В таблице **нет учителей** и **нет никаких id** — только текст.

## 3. Таблица Excel «расписание по учителям» (второй входной файл)

Тот же лист и та же сетка, но в ячейках — учитель и кабинет: `Родионова С.Е. (205)`,
а при делении — несколько ФИО: `Малиновская Т.В., Ахидов К.А. (215,110)`.

Особенности записи ФИО, которые учитывает конвертер:
* инициалы с одной буквой («С.Е.»), с двумя буквами отчества («О.Вл.» — так различают
  двух Ольг Кузнецовых: Владимировну и Васильевну), опечатки («Бочкарева Е..С.»);
* «ё» в фамилиях («Лёшина») нормализуется;
* кабинеты в этой таблице совпадают с таблицей по предметам (проверено: 1554/1554),
  но программа всё равно сверяет их и предупреждает при расхождении.

Зачем нужен файл: в формате XML учитель «зашит» в строку плана (`csg/@tid`), а в таблицах
его нет. Вторая таблица позволяет (а) выбирать точную строку плана, когда у предмета
несколько групп с разными учителями, (б) находить расхождения сетки школы с планом системы
(учитель таблицы не ведёт выбранную строку плана), (в) проверять занятость учителей
до импорта.

## 4. Как форматы соотносятся (правила маппинга конвертера)

| В Excel | В XML | Откуда берётся id |
|---|---|---|
| значение в колонке A («Пн») | `<Day id wd name>` | справочник дней эталона |
| номер в колонке B (`3`) | `<Lesson timeId>` | `LessonTimes`: `timeId = number + 1` |
| название колонки («5а») | `<class id>` в `Plan` | справочник классов (+ файл соответствий) |
| предмет из ячейки | `<csg id>` внутри `<Lesson>` | строки плана класса: совпадение названия (точное → аббревиатура → перестановка слов → нечёткое), выбор группы по рангу и истории кабинетов |
| кабинет из ячейки (`311`) | `roomid` | справочник кабинетов (+ файл соответствий) |
| ФИО из таблицы по учителям | уточняет выбор `<csg id>` | `csg/@tid` строки плана сверяется со списком tid, полученных из ФИО |
| — | `sid`, `pclassid`, `hrsweek` | уже содержатся в найденной строке плана |

Группы: если у предмета несколько строк плана (п.1/п.2), конвертер берёт свободную на данном
уроке, а при наличии истории в эталоне — ту, за которой «закреплён» кабинет из ячейки.

Результат: секции `LessonTimes`, `teachers`, `subjects`, `Rooms`, `Plan` копируются из эталона
**байт в байт**, пересоздаётся только блок `<TimeTable>` — идентификаторы и форматирование
системы сохраняются полностью.

## 5. Что не переносится из Excel в XML (и почему)

| Значение в таблице | Причина |
|---|---|
| «Разговоры о важном», «Россия — мои горизонты», «Семьеведение», «ОДНКНР» | предметов нет в справочнике системы — без `sid` строку плана не создать |
| кабинеты `112`, `БАС`, `IT куб 1/2`, `акт.зал`, `каб.пр.дея` | кабинетов нет в справочнике системы |
| «Информатика» для 5–6 классов | в плане этих классов предмет называется «Программирование и алгоритмика» — лечится правилом в `aliases.json` |
| колонка `11и` | делится на два профильных класса; распределение — по часам в плане либо правилом `by_subject` |

Всё перечисленное попадает в отчёт и во вкладку «Соответствия», где задаётся правилом
в один клик и сохраняется в `aliases.json`.
